# X (Twitter) sweep: real-world LLM failures

> Bot search of X over the last 12 months, English, preferring engagement or concrete examples. 51 posts returned; 3 duplicates merged and 4 off-topic posts excluded, leaving 44. **Verification pass 2026-10-29:** X.com and XSearch returned 403 / unavailable from this environment. Must-reads were checked via linked papers, public repos, Anthropic/DAPLab writeups, LinkedIn cross-posts, and tweet mirrors where available. Items marked `yes (via …)` are claim-verified without opening the live tweet; `no` means still unverified.

## 1. Takeaways

- **Losing context or state is the biggest real-world complaint** (9 items), and most of it is about harnesses: compaction, sessions, memory, multi-agent shared state. The Fermat formalization case (agents lost project state, fixed by external structured memory) is the clearest example.
- **Tool hallucination is close behind** (7): invented endpoints, URLs, tool calls and package names, often treating empty or failed results as real data.
- **Breaking stated rules** (6) shows up mostly in coding agents: ignored file formats, styles and approaches, sometimes with a made-up justification.
- **Faithfulness has strong research posts** (7), including two that matter for the design: a paper finding models commit to an answer before the reasoning finishes ("premature confidence"), and work showing most unfaithful-CoT detectors perform near chance.
- **Contamination and saturation** (5) are discussed around ARC-AGI, FrontierMath and ExploitBench; ErdosBench is kept private specifically to avoid it. Supports our generator-plus-private-seeds design.
- **Thin on X:** greedy / no-planning failures and "changed the numbers and it failed". These need paper sources, not social posts.
- **Model vs harness:** about a third of items are mainly harness problems. Every pain point needs this label before it drives a benchmark choice.

## 5. Must-read item notes

### 46. Premature confidence
- **Link:** https://x.com/Jingchug/status/2060198436285136971 · paper https://arxiv.org/abs/2605.24396
- **What failed:** models settle on an answer before the reasoning chain finishes; later steps rationalize it.
- **Why it matters:** if the answer is decided early, a probe at the question or early in reasoning should predict it. Tests H10 and bears on faithfulness and misplaced retrieval.

### 13. Faithfulness metrics near chance
- **Link:** https://x.com/GurYoav/status/2059292492412133639
- **What failed:** 8 published methods for detecting unfaithful CoT mostly performed near chance.
- **Why it matters:** supports our rule of never trusting written reasoning. Their fix (tasks whose output reveals which steps were used) is a design idea for our faithfulness tests.

### 36. Fermat agents lost project state
- **Link:** https://x.com/Chi_Wang_/status/2096313850870288392
- **What failed:** multi-agent formalization failed because agents lost shared state, not because of the maths.
- **Workaround and result:** external DAG of statements and proofs; reportedly finished in about 11 days.
- **Why it matters:** a clean real-world case for the state-tracking dimension and for "written state" as a harness fix.

### 18. Flags bad tool data, then uses it
- **Link:** https://x.com/steverab/status/2033906503896154359
- **What failed:** the reasoning says a tool value is unreliable, then the answer uses that value.
- **Why it matters:** program-checkable reasoning-action mismatch; could become a test (plant a flagged-bad tool value, check whether it reaches the answer).

### 12. Qwen3-8B picks the first item
- **Link:** https://x.com/adam_karvonen/status/2090879833777873190
- **What failed:** asked to choose from a list, the model took the first entry and invented a reason.
- **Why it matters:** an open model we can rerun; position bias is easy to test by shuffling options.

### 41. Hallucinated API endpoint
- **Link:** https://x.com/arvidkahl/status/2072435617867194543
- **What failed:** agent called a made-up endpoint, treated null replies as missing data and blamed the API.
- **Why it matters:** combines tool hallucination with wrong reasoning on given data. A checkable tool-environment test.

### 44. Rewrote an already-fixed bug
- **Link:** https://x.com/DanielGlejzner/status/2081675505758040135
- **What failed:** 5 to 6 iterations on a bug already solved; only style changed each time.
- **Why it matters:** the reverse of stopping early: the model cannot tell the goal is met. Feeds the possible "goal-completion calibration" dimension from the taxonomy crosswalk.

### 34. Claude Code snuck in changes
- **Link:** https://x.com/yacineMTB/status/2015226602804670864
- **What failed:** instructions quietly not followed; bugs found later by another tool.
- **Why it matters:** high engagement; links rule-breaking with false completion claims.

### 2. Qwen hallucinates file-proxy URLs
- **Link:** https://x.com/wtogami/status/2107331237635600847
- **What failed:** invented URLs, every call returned 403, hundreds of junk tokens per attempt.
- **Workaround and result:** blocking plugin and public reproducer; partly worked.
- **Why it matters:** reproducible on an open model; shows how failed tool calls degrade later reasoning.
